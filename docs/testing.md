# 验证范围

## 已验证

- 启动配置回归先在旧代码上失败，修正后确认 Chromium 固定入口参数、回环绕过列表、Node 环境代理启用及后端代理地址。
- 从迁移后的源码重新运行测试，当前用户安装清单与实际可执行文件的只读定位也通过；CI 使用 `--offline` 跳过此项。
- 本地 Node 24.21.0 实连接：禁用环境代理时 `.invalid` 测试域名解析失败，代理没有收到连接；启用后 HTTPS 返回 200，WSS 升级握手返回 101，经过真实 Relay 和模拟上游代理。
- 两次请求可能复用一个 CONNECT 隧道；这也是无法保证立即迁移旧连接池的原因。
- 核心转发测试覆盖直连、HTTP、CONNECT、两出口切换、旧连接保留、二进制背压、半关闭、请求体、信息响应、拒绝和超时、回环递归保护及停止收拢。
- 诊断日志跨实例保留、换行中和、约 1 MiB 轮转、上游状态码、连接编号及失败阶段。
- Release / win-x64 构建和 WPF 静态预览渲染。

## 尚未验证

- 真实 Desktop 登录、模型响应和各云端 WebSocket 在每种 VPN 下的端到端验收。
- 所有 Desktop 内部自定义代理/连接器均遵循本工具设置。
- 运行中的真实任务跨 VPN 无缝恢复。
- 所有 Windows 多显示器与混合 DPI 场景。

本地 TLS fixture 使用一次性自签名证书，只在测试客户端关闭证书校验；生产 HTTPS 检测保留默认严格校验，不修改系统信任库。

`--offline` 仅跳过安装包查询，不跳过回环协议测试；测试不访问真实账号，也不启动或关闭 Desktop。
